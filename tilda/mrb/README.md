# Mr B Academy — лендинг под TikTok UGC-трафик

Блоки для Тильды. Мобайл-фёрст, без внешних библиотек, один шрифт (Manrope 400/800).
Целевое действие — заявка в попапе, лид уходит в AmoCRM через штатную форму Тильды.

---

## ⚠️ Технический регламент не был приложен

В брифе указано:

> Запускать вместе с `tilda-html-block-prompt.md` — он идёт как технический регламент
> (изоляция CSS, префиксы, скоуп JS, брейкпоинты Тильды, запреты).
> При конфликте требований приоритет у технического регламента.

**Этого файла нет** — ни в репозитории, ни в истории git (проверено по всем веткам).
Блоки собраны по стандартным правилам вставки в Тильду, перечисленным ниже.
Пришлите регламент — сверю и приведу в соответствие; расхождения, если они есть,
будут в этих пунктах:

| Что применено | Значение |
|---|---|
| Префикс классов | `mrb-` (блок), `mrbq-` (квиз), `mrbs-` (простая форма) |
| Изоляция CSS | все правила вложены в `.mrb` / `.mrbq` / `.mrbs`; ни одного глобального селектора, `body`/`html`/`*` не стилизуются |
| Переменные | объявлены на `.mrb`, **не** на `:root` |
| Скоуп JS | IIFE + `'use strict'`, ни одной глобальной переменной, все выборки от корня блока |
| Повторная инициализация | флаг `data-mrb-init` — редактор Тильды перерисовывает блок |
| Брейкпоинты | `1200 / 980 / 640 / 480` (max-width) + одна min-width-точка на 981 и 641 |
| z-index | sticky-панель `900` — заведомо ниже попапов Тильды (~9999) |
| Запрещённое | нет `<html>/<head>/<body>`, нет внешних библиотек, нет фейковых таймеров и «осталось N мест» |

## Установка

### 1. Лендинг

1. Новая страница → блок **T123 «HTML-код»**.
2. Вставить `block.html` целиком.
3. В настройках страницы убрать шапку и футер Тильды — на первом экране не должно
   быть меню и лишних ссылок (требование брифа).

### 2. Попап

1. Добавить блок попапа (**T480** или zero-block popup).
2. В настройках попапа задать имя: `diagnostika`.
3. Внутрь попапа — блок **T123** с содержимым `popup-quiz.html`.

Все кнопки лендинга ведут на `#popup:diagnostika`. Если имя попапа другое —
поменять во **всех** ссылках блока (их 7, ищите `#popup:diagnostika`).

### 3. Шрифт

Блок подключает Manrope сам, через `<link>`. Для лучшего LCP лучше перенести
подключение в **Настройки сайта → Шрифты → свой шрифт** и убрать `<link>` из блока —
тогда шрифт грузится в `<head>`, а не из тела страницы.

## Форма и AmoCRM

Собственного сабмита в блоках нет. Отправку выполняет Тильда.

### Настройка

1. **Настройки сайта → Формы → AmoCRM** — подключить нативную интеграцию.
2. Поля формы придут с этими именами — их и маппить на поля сделки:

| Поле | Имя | Вариант |
|---|---|---|
| Имя | `Name` | оба |
| Телефон | `Phone` | оба |
| Цель | `Цель` | только квиз |
| Срок | `Срок` | только квиз |
| Уровень | `Уровень` | только квиз |
| Источник | `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term` | оба |
| TikTok click id | `ttclid` | оба |
| Адрес страницы | `page_url` | оба |
| Вариант формы | `form_variant` (`quiz` / `simple`) | оба — по нему сравнивать А/Б |

`Цель / Срок / Уровень` — те самые четыре критерия квалификации, которые уже
заведены в CRM. Менеджер видит квал до первого касания.

3. **Страница «Спасибо»** — создать отдельно и указать её в настройках формы
   (*После отправки → Перенаправить на страницу*). События пикселей вешать там:
   так событие не теряется и не задваивается.

### Важно про проверку

Форма инициализируется через `tildaForm.init()` и работает **только на
опубликованной странице**. В превью и в редакторе `tildaForm` не существует —
отправка молча не сработает. Это не баг блока.

Скрипт ждёт появления `tildaForm` до 6 секунд (40 попыток × 150 мс) и не падает,
если его нет.

## Мультилендинг под креативы

Первый экран меняется через GET-параметры — без переверстки и без копий страницы:

```
/?h=Сдать IELTS 7.0 с нуля за год
/?h=IELTS за 10 недель&sub=Преподаватель с опытом экзаменатора Cambridge
```

- `?h=` — заголовок H1, `?sub=` — подзаголовок;
- без параметров остаётся текст из разметки (`data-mrb-default`);
- подстановка через `textContent`, обрезка до 160 символов —
  разметка из параметра **не исполняется** (проверено инъекцией `<img src=x onerror=...>`);
- слоты помечены `data-mrb-slot="h1"` и `data-mrb-slot="sub"`.

Заголовок должен продолжать мысль ролика, а не начинаться заново —
под каждую связку свой `?h=` в ссылке объявления.

## Аналитика

Ставится **не в блок**, а в настройки сайта и на страницу «Спасибо».

### TikTok

1. **Настройки сайта → Аналитика** — вставить базовый код TikTok Pixel.
2. На странице «Спасибо» — событие `SubmitForm` (или `CompleteRegistration`,
   если так заведено в рекламном кабинете).
3. **Events API** — серверная передача. Обязательно передавать `ttclid`
   для матчинга: он приходит в `?ttclid=` и уже лежит в скрытом поле формы,
   откуда попадает в AmoCRM.

`ttclid` и все UTM дублируются в `sessionStorage` и восстанавливаются оттуда,
если параметр потерялся при переходе внутри сайта (проверено).

### Meta

Ставить параллельно, даже если бюджет сейчас весь в TikTok — иначе при
перераспределении бюджета не будет накопленных данных.

### UTM

Размечать **на уровне объявления**, чтобы в AmoCRM был срез по конкретному
UGC-ролику. Минимально:

```
utm_source=tiktok&utm_medium=cpc&utm_campaign={campaign}&utm_content={ad}&utm_term={creative}
```

### Цель оптимизации

Цель в CRM — **квал**, а не «заявка». Иначе оптимизация уедет в объём
дешёвых нецелевых лидов. Ориентир из брифа — 60–70% квала.

## А/Б-тест попапа

Собраны оба варианта:

- **A — квиз** (`popup-quiz.html`): 3 вопроса + контакты, лестница микро-обязательств.
  Менеджер получает квал сразу.
- **B — простая форма** (`popup-simple.html`): имя + WhatsApp.

Различает их скрытое поле `form_variant`. Как сравнивать: по **доле квала**
и стоимости квала, а не по конверсии в заявку. Квиз обычно даёт меньше заявок,
но выше их качество — если считать только CR формы, вывод получится обратный правде.

Чтобы запустить: развести варианты по двум попапам (`diagnostika` / `diagnostika-b`)
и подавать на них трафик через А/Б-тест страниц Тильды либо разными ссылками
в объявлениях.

## Ассетов нет — что нужно загрузить

Ничего своего в проекте не было, всё ниже — плейсхолдеры в вёрстке.

| Что | Где в блоке | Формат |
|---|---|---|
| **Фото преподавателя** | `.mrb-expert-photo`, сейчас SVG-силуэт | 4:5, от 640×800, WebP |
| **Скриншоты баллов** | `.mrb-shot` ×2 в секции «Результаты» | 3:4, читаемый скрин результата |
| **Отзывы** | `.mrb-result.mrb-card` ×2 | текст + имя + балл |
| **Логотип** | сейчас его нет нигде | по брифу — словесный леттеринг «Mr B Academy» |
| **Favicon** | настройки сайта | 512×512 PNG |
| **OG-картинка** | настройки страницы | 1200×630, критично для репостов |

Стоки согласованы — под фото интерьера/занятий можно брать сток,
но **фото преподавателя должно быть настоящим**: на нём держится весь оффер
и главный дифференциатор от трёх конкурентов без личного бренда.

Секция «Результаты» **схлопывается сама**, пока внутри нет ни одного
элемента `.mrb-result` — можно опубликоваться без неё и наполнить позже.
Удалите заглушки `<li class="mrb-result ...">` целиком, и секция исчезнет
(проверено).

## Тексты под замену

Всё содержательное взято из брифа, но эти места нужно подтвердить у клиента:

| Место | Сейчас | Что уточнить |
|---|---|---|
| H1 | «Сдать IELTS на нужный балл — за 10 недель» | согласовать с текстом ролика |
| Полоса доверия | 15+ / Cambridge / до 6 / Астана | точные формулировки регалий |
| «15+ лет» | счётчик до 15 | если стаж другой — `data-mrb-count` |
| Отзывы | «Текст отзыва ученика» | реальные |
| Баллы в отзывах | Band 7.5 / 7.0 | реальные |
| Адрес | «Астана, левый берег» | точный адрес, если он публичный |
| Юр. текст под кнопкой | про обработку перс. данных | сверить с политикой на сайте |

Формулировки про сроки (**«от 2–3 месяцев до года+»**) и про отсутствие гарантии
балла в FAQ намеренно honest-стайл: они отсекают «а мне обещали 2 месяца»
до менеджера и работают на квал. Смягчать их — терять смысл блока.

## Что проверено

Chromium, реальный рендер, ширины 360 / 390 / 480 / 640 / 768 / 1440:

- **первый экран умещается в 390×844 без скролла** — 804px из 844 ✓
- горизонтального скролла нет ни на одной ширине ✓
- ошибок в консоли нет ✓
- Manrope с кириллицей грузится ✓
- квиз: шаги, прогресс-бар, блокировка перехода без ответа, «Назад», авто-переход после выбора ✓
- маска телефона: `7019998877`, `87019998877`, вставка `+7 701 999 88 77` → `+7 (701) 999-88-77` ✓
- валидация на `blur`, состояние кнопки при отправке ✓
- UTM + `ttclid` + `page_url` попадают в скрытые поля; восстановление из `sessionStorage` ✓
- `?h=` подставляется, инъекция HTML не исполняется ✓
- sticky-CTA появляется после 40% скролла и прячется на финальном экране ✓
- секция «Результаты» схлопывается без материалов ✓
- все элементы проявляются даже при мгновенном прыжке в конец страницы ✓
- тач-цели ≥ 48px ✓

**Не проверено и проверяемо только после публикации:** фактическая отправка
формы в AmoCRM (нужен живой `tildaForm`), срабатывание пикселей,
поведение внутри реального попапа Тильды.

### Известные ограничения

- Ввод `77019998877` даёт `+7 (770) 199-98-87`. Это осознанно: `770` —
  реальный код Tele2/Altel, и срезать ведущую семёрку как «код страны»
  нельзя, иначе сломаются все номера на 770. Восьмёрка срезается корректно.
- `100svh` на первом экране: в старых браузерах без поддержки `svh`
  есть фолбэк на `100vh` — там первый экран может быть чуть выше
  из-за адресной строки.
